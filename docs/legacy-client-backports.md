# 老版单机客户端兼容修复

2026-10-16：保留 1.0.192 客户端、老资源和 `ST_OFFLINE`。没有新增游戏服务端，也没有复制朋友的账号、认证、公钥、SDK 或遥测代码。

## 本轮实际移植

`runtime/offline_compat.py` 在练习场控制器初始化后安装。来源是本机 1.0.304 客户端相对于 1.0.192 的函数差异，不能归因为朋友原创的修复记录。

| 修复 | 新版依据 | 老版适配 |
|---|---|---|
| 金币通知只由当前玩家发出 | `Hero.set_cash` 增加 `self == BigWorld.player()` 判断 | 保留老通知逻辑，过滤其他实体的事件，避免对手的金币变动干扰玩家观察者 |
| 教学输入返回契约 | `PlayerHero.handle_special_event` 新版保留教学回调并返回 False | 练习场使用新版返回值；大厅保持原处理方式 |
| 受控状态的传送判断 | `PlayerHero.allow_tp` 增加 `debuff.can_attack()` 条件 | 在练习场补充该判断，保留原来的状态、倒计时等条件 |
| 天赋撤销通知分流 | `PlayerHero.revert_evolution_item` 新增天赋分支；两个天赋界面增加撤销刷新 | 仍调用老版实体的原生撤销，只在天赋分支刷新天赋列表和完整进化树；兼容没有新版撤销计时器的老界面 |

所有钩子保留原方法，重复安装不会叠加调用。普通装备撤销继续使用原处理流程。

天赋这一项修复的是**已经发生的原生天赋撤销事件如何更新界面**，并不代表已经实现离线天赋购买、完整天赋效果或装备特殊修饰器。

另修复现有启动脚本的可选外观加载：只有 `saber_mod.py` 存在时才加载。保留已有 Saber 外观代码和配置。

## 对照得到的事实

为避免把操作码变换误判为修复，本次用 19,024 组可对齐函数推断出 100 项新版到旧版操作码映射，再对照有关模块。静态结果：

- `PracticeAIHero` 的 8 个代码对象一致。
- 冷却管理 `captain/cdmgr` 的 25 个代码对象一致。
- `HeroSkillMgr` 的 92 个代码对象一致。
- `logic/ClientItem` 的 27 个代码对象一致。
- `NewPlayerOfflineManager` 的 24 个代码对象一致。
- `PracticeRoomHelper` 的 32 个一致；另一个变化涉及新版行为检查器。
- `Hero` 模块有 863 个一致、23 个有差异、63 个新增。新增内容包含大量账号、网络诊断、遥测和在线检查，并非都适合单机。

“一致”指归一化操作码后，函数指令、名称表和常量等相同；不等于两个完整运行环境相同。差异也不自动等于修复。

练习入口的新版差异主要增加点击记录；创建房间、进入教学仍调用服务器。两版均存在某个按钮或类，不能据此认定新版客户端已经包含对应的单机实现。

分析脚本：`C:\wildfire-gpt\analysis\compare_offline_versions.py`。
结果：`C:\wildfire-gpt\analysis\offline_backport\gameplay_comparison.json` 和 `changed_gameplay_functions.json`。
